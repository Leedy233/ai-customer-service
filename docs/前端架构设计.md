# frontend 前端架构设计（Vue 3 + TS + Vite）

> 状态：设计稿，待确认。未生成任何页面代码，未移动任何现有文件。
> 后端事实基线：见《项目审查与前后端分离升级方案.md》。当前后端仅 7 个业务接口、Session 认证、**无角色字段、无管理端接口、无读侧 REST、SSE 为 v1 裸文本流**。本设计所有"对接"均区分三档：REAL（现在就有）、PLANNED-U（用户端补齐接口，审查方案阶段一~三）、PLANNED-A（管理端新增接口）。不假设任何不存在的接口。

## 0. 设计原则

1. **契约先行**：先冻结 `docs/api-contract.md`（含 PLANNED 档），前端按契约开发，缺接口用本地 mock 顶替，后端就绪后关 mock 开关，不改业务代码。
2. **加法不重写**：后端旧接口保留；前端 api 层做 v1/v2 双适配器，切换只改配置。
3. **同域认证**：dev 用 Vite proxy、prod 用 nginx 反代，Cookie 同域，**零 CORS 代码、不引 JWT**。
4. **两个模块一套工程**：用户端/管理端共用 http/stores/组件库，靠 layout + 路由 meta.roles 隔离，不拆两个仓库。
5. **依赖克制**：只引用户指定栈 + 4 个有明确理由的小依赖（见 §9）。

## 5. Axios 请求封装（api/http.ts）

- 实例：`baseURL=import.meta.env.VITE_API_BASE`（dev/prod 均 `/ai`，同域代理）；`withCredentials=true`；timeout 30s（同步 chat 单独 120s）；headers `X-Requested-With: XMLHttpRequest`。
- 请求拦截：无 token 注入（Cookie 自动带）；mock 开关在 api 模块层判断，不进拦截器。
- 响应拦截（**过渡期双通道归一**，后端审查阶段一完成后删分支）：
  1. HTTP 401 或 body.code===401 → 抛 ApiError(401)；全局去重一次：userStore.clear() + router.push(/login?redirect=当前) + ElMessage。
  2. HTTP 429 / body.code===429 → ApiError(429)，ElMessage 节流 3s。
  3. body.code!==200 → ApiError(code,message)。
  4. 成功 → 解包返回 `res.data.data`（泛型 `http.get<T>` 直接拿 T）。
- ApiError extends Error {code, httpStatus, message}；views 用 try/catch + ElMessage，不在组件里判 code。
- 取消：每个列表页 onUnmounted abort 自己的 AbortController；SSE 不走 axios（§6）。
- 类型：types/api.ts 定义 `ApiResponse<T>`、PageResult<T>、LoginDTO、各 VO；与 docs/api-contract.md 一一对应。

## 6. SSE 流式通信方案

### 6.1 传输选型

- **fetch + ReadableStream 手动解析**（utils/sse-parser.ts 状态机：按空行分帧，累积 `event:`/`data:` 多行，data 多行以 `\n` 连接，忽略 `:` 心跳注释）。
- **禁用 EventSource**：不支持 POST/自定义头；自动重连会把同一个问题重发一遍（灾难）。
- 断线/错误**不自动重试**；UI 给"重试"按钮由用户显式触发。

### 6.2 双版本适配器（VITE_SSE_VERSION）

| | v1（REAL，现在） | v2（PLANNED-U，审查阶段三） |
|---|---|---|
| 请求 | GET /ai/chat/stream?conversationId&message | POST /ai/v2/chat/stream JSON body |
| 帧 | 裸 `data:<文本>` | `event: delta/card/done/error` + JSON data |
| 结束 | 流关闭即 done | done 事件带 usage |
| 错误 | 连接静默断 → UI 提示"连接中断" | error 事件带 code/message |
| 卡片 | 无（v1 期 OrderCard 由 done 后调 order.detail 补齐，替代正则） | card 事件直出 OrderVO |

useSSE(url, {method, body, onEvent, signal}) 统一两种模式；useChatStream 把事件落进 chat store。

### 6.3 渲染与生命周期

- delta 进缓冲，requestAnimationFrame 每帧批量 flush（≈16ms），避免逐 chunk 触发整列表重渲染。
- Markdown：marked 解析 + DOMPurify  sanitize 后 v-html（RAG 答案含列表/表格）；streaming 中仅渲染已 flush 文本。
- stop()：AbortController.abort → 服务端 doFinally 落审计（后端阶段三配套）；UI 标记"已停止"。
- 路由离开/组件卸载自动 stop；同 conv 重复 send 先 stop 旧流。
- 401（流开始前的响应状态）→ 走 http 层同一路由跳登录逻辑。
- 心跳：v2 服务端 15s comment 帧，parser 忽略；nginx `proxy_read_timeout 300s` + `proxy_buffering off`。

## 8. 登录认证方案

- **机制复用后端 Session**：JSESSIONID Cookie，HttpOnly；不引 JWT、不存 token 于 localStorage。
- **同域链路**：dev `vite proxy /ai → http://localhost:8080`（Cookie host-only 不区分端口，可直接用）；prod nginx `location /ai { proxy_pass http://app:8080; }`。跨域场景本期不做（若将来必须：CORS allowCredentials + 显式 origins + SameSite=None; Secure，需 HTTPS，另行评审）。
- **登录流**：LoginView → auth.login → auth.me 入 user store → redirect 回原页；守卫见 §3.2。
- **会话过期**：任何 401（含 SSE 起始响应）→ 清 store → 跳登录带 redirect；ElMessage 一次。
- **CSRF**：同域 + SameSite=Lax + 变更操作全 JSON POST（跨站 JSON 触发 preflight 被 CORS 挡）→ 当前威胁模型足够；不引 CSRF token 框架。
- **XSS**：Cookie HttpOnly 偷不到；聊天 markdown 经 DOMPurify；v-html 仅 sanitize 后一处。
- **管理端隔离**：路由 meta.role + 后端 /ai/admin/** 拦截器双保险；前端开关只控可见性，**安全边界在后端**。
- 后端配套（PLANNED）：登录改 JSON body、changeSessionId、session.timeout 显式配置、ai_user.role 列。
